# Solana x402 AI Proxy

Локальное демо шлюза, которое рассчитывает цену по фактическому usage AI-провайдера и раскрывает ответ только после подтверждённого платежа в Solana Devnet. При ставке `r` lamports за токен платёж равен `total_tokens × r`. Сервер сверяет на Solana перевод ровно на рассчитанную сумму.

## Гипотеза и один сценарий

Гипотеза: разработчик небольшого AI-приложения хочет платить за фактические токены отдельных запросов без подписки и собственного платёжного аккаунта. Спрос и готовность платить пока не подтверждены.

Happy path: **подключить Phantom → ввести вопрос → получить точный расчёт токенов и цены → подтвердить перевод в Devnet → получить ответ**. Поддержан один текстовый запрос к Gemini, нативный SOL, фиксированная ставка за токен и одна проверяемая транзакция. Смарт-контракт не нужен для этого сценария.

## Локальный запуск

Нужны Docker Compose, Phantom, тестовые SOL Devnet и ключ AI-провайдера. Скопируйте пример конфигурации:

```sh
cp .env.example .env
```

Заполните в `.env` публичный адрес получателя `SOLANA_WALLET_ADDRESS` и `UPSTREAM_API_KEY`. Ставка по умолчанию для демо — **10 lamports за токен**; её можно изменить через `PAYMENT_PER_TOKEN_LAMPORTS`. Это тестовая ставка, а не подтверждённая экономика продукта. Никогда не кладите в `.env` приватный ключ: Phantom подписывает перевод локально, серверу нужен только публичный адрес.

Запустите сервис:

```sh
docker compose up --build
```

Откройте `http://localhost:8080`. Подключите Phantom, включите в нём Testnet Mode и используйте сеть Devnet. Введите вопрос и следуйте статусам на экране. Сервис доступен только через loopback `127.0.0.1`. Получить тестовые SOL можно через [Devnet faucet](https://faucet.solana.com). Остановка: `Ctrl+C` или `docker compose down`.

Приложение подписывает транзакцию в Phantom, но отправляет подписанные байты только через Devnet RPC. В интерфейсе указана демо-среда; Devnet SOL не имеют реальной стоимости. Mainnet в сценарии не используется.

## Как устроен расчёт

1. Прокси запрашивает у Gemini обычный, не потоковый ответ с `reasoning_effort=low` и ограничением до 768 выходных токенов; читает фактический usage (`total_tokens` или эквивалентные поля OpenAI/Gemini). Интерфейс добавляет инструкцию для понятных ответов с примером; её токены тоже учитываются в расчёте.
2. Ответ остаётся в ограниченном временном кэше на сервере (до 5 минут, не более 32 активных расчётов) и не отправляется браузеру до оплаты. Прокси возвращает HTTP `402`, число токенов, ставку, итоговую сумму и ID расчёта.
3. Браузер отправляет в Devnet точную сумму. Сервер проверяет успешный перевод System Program на заданный адрес с совпадающей суммой, затем выдаёт сохранённый ответ. Если провайдер не вернул фактический usage, расчёт отклоняется без запроса платежа.

Котировка отклоняется до платежа, если сумма превышает точный целочисленный диапазон браузерного кошелька; это исключает округление lamports между расчётом и подписью.

Запрос к AI выполняется **до** платежа, чтобы узнать фактическое число токенов. Phantom откроет подтверждение только после успешного ответа Gemini и создания котировки; если Gemini вернул ошибку, платёжное окно не вызывается. Поэтому оператор демо может оплачивать запросы к Gemini, для которых пользователь не завершил оплату. Лимит активных расчётов и привязка сервиса к localhost ограничивают сценарий локальным тестом, но не являются защитой для публичного запуска.

Платёжный кэш и ответы хранятся только в памяти и теряются при перезапуске. Поддерживается только фиксированная ставка за токен и текстовый Gemini-запрос; мультимодальность, SPL-токены, возвраты и постоянный учёт отложены.

## План проверки

Календарная оценка и доступность тестовых пользователей неизвестны. Для локального прохода предполагается один сопровождающий разработчик:

1. **Конфигурация:** задать Devnet адрес и AI API key; приложение должно отказаться запускаться без них и не принимать другой Solana RPC.
2. **Автоматические проверки:** `go test ./...` подтверждает расчёт цены, разбор форматов usage OpenAI/Gemini, закрытие ответа до оплаты, повторную доставку без второго списания и правильный Gemini URL.
3. **Ручной Devnet проход:** пройти интерфейс с Phantom и убедиться, что ответ появляется только после подтверждённого перевода.
4. **Пользовательский тест:** провести задачу минимум с пятью разработчиками, если они доступны; записать поведение по метрикам ниже. Не подменять отсутствующих участников предположением.

Если провайдер не возвращает фактический usage, демо должно отказать закрыто. При ошибках Gemini интерфейс показывает HTTP-статус и безопасную подсказку: проверить `UPSTREAM_API_KEY` для 401/403, `UPSTREAM_BASE_URL` и `AI_MODEL` для 404, квоту для 429. Тело ответа провайдера намеренно не выводится. Если Devnet/RPC недоступен, оставить ответ закрытым и дать повторить доставку той же подписанной транзакцией; не отправлять новый платёж автоматически.

## Проверка MVP

Технический проход считается успешным, если одновременно выполнены условия:

- ответ Gemini сообщает ненулевое фактическое число токенов в поддерживаемом поле usage;
- показанная сумма точно равна `total_tokens × PAYMENT_PER_TOKEN_LAMPORTS`;
- до подтверждения транзакции ответ не появляется в браузере;
- перевод Devnet на один lamport меньше, неверный адрес, повторная подпись и неподтверждённая транзакция не открывают ответ;
- один точный перевод открывает только соответствующий ответ, а повтор получения после сетевого сбоя использует ту же подпись и не требует второго платежа.

Для нейтральной проверки с людьми дайте разработчику задачу: «Получите ответ на свой вопрос через демо». Попросите вслух описывать ожидания и наблюдайте молча. Запишите для каждого участника: завершил ли он сценарий без помощи, понял ли цену до подписи, сколько заняло получение ответа, был ли повторный платёж и получил ли он ожидаемый ответ. Не спрашивайте, нравится ли интерфейс. Предварительный порог для следующего шага — 4 из 5 подходящих разработчиков завершают сценарий без подсказки; это планируемый критерий, не уже полученный результат.
